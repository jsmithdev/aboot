# Decisions
- 2026-11-14: Added `PREDO.md` as a brainstorming stage ahead of `POSSIBLES.md`; `AGENTS.md` workflow now documents the PREDO → POSSIBLES → TODO pipeline.
- 2026-11-14: Renamed the pipeline to THINKDO.md (brainstorm) → PREDO.md (potential items) → TODO.md (processed); added a `PREDO.md` placeholder to `examples/` so new projects get the full pipeline.
- 2026-11-14: Moved the THINKDO → PREDO → TODO process docs out of `AGENTS.md` into `README.md`; brainstorming/curating is planning work, not per-loop agent work.
- 2026-11-14: Built-in template lives in `examples/` and is embedded via `include_str!` — single source of truth, no sync step between repo files and the binary.
- 2026-11-14: Managed sections wrap only `AGENTS.md`/`CLAUDE.md`/`justfile`/`.editorconfig` (markers in each file's native comment syntax), so `aip update` never rewrites user-owned files like `TODO.md` or `DECISIONS.md`.
- 2026-11-14: `.aip.json` manifest stores scaffold vars (name, description, stack, agent, version) so `update`/`status`/`list` are deterministic across sessions.
- 2026-11-14: Internal template vars `{{stack_section}}`, `{{justfile_commands}}`, `{{agent_file}}` keep stack-specific content out of user-facing `{{name}}`/`{{description}}`/`{{date}}`/`{{stack}}`.
- 2026-11-14: `--agent claude` reuses the `AGENTS.md` template with the marker's `file=` attribute rewritten to `CLAUDE.md`, so both stay in sync from one source.
- 2026-11-14: `aip add` installs everything except `README.md` (user content), and `--task` only seeds a TODO.md it creates.
- 2026-11-14: Short SPDX licenses (MIT, ISC, BSD-2/3, Unlicense, 0BSD) are embedded as full text; other SPDX ids get a pointer file to spdx.org instead of stale embedded text.
- 2026-11-14: `aip todo add/done` take `--path` instead of a positional because clap rejects a non-required positional before a required one.
- 2026-11-14: Exit codes are 0 ok / 1 error / 2 usage (clap); `--json` emits one pretty JSON object with errors as `{"error": ...}`.
- 2026-11-14: cargo-dist release is config-only (`dist-workspace.toml` with `[profile.dist]`); the release workflow is generated by `cargo dist generate` rather than hand-maintained.
- 2026-11-14: CI (`.github/workflows/ci.yml`) runs on stable with rustfmt+clippy components: fmt check, `clippy --all-targets -- -D warnings`, `cargo test`.
- 2026-11-14: Renamed the tool from `aip` to `aboot` (Agent Bootstrap); clean break with no migration (markers are now `aboot:begin/end`, manifest `.aboot.json`) because nothing was ever released under the old name.
- 2026-11-15: Renamed the workflow pipeline to an Agile/Scrum framing — `THINKDO.md` → `REQUIREMENTS.md` (BA/client needs), `PREDO.md` → `BACKLOG.md` (groomed stories), `TODO.md` → `BOARD.md` (active dev board) — and the `aboot todo` command to `aboot board` (JSON key `todo` → `board`), matching industry-standard backlog/board vocabulary.
- 2026-11-15: `aboot add` scope filters `--md-only` (`-m`) / `--agent-only` (`-a`) — clap has no multi-char shorts, so the requested `-mo`/`-ao` became `-m`/`-a`; the flags are mutually exclusive since the agent file is a markdown subset.
- 2026-11-15: `--version` / `-v` is an explicit flag instead of clap's built-in, because the built-in `--version` cannot take a short form (auto-generated args are added at build time, so `mut_arg` can't reach them); the subcommand became optional, so bare `aboot` now prints help (exit 2) instead of a "requires a subcommand" error.
- 2026-11-15: AGENTS.md workflow now derives session mode from context files — `REQUIREMENTS.md`/`BACKLOG.md` without `BOARD.md` means planning (no board edits, no `aboot board add`/`done`), `BOARD.md`-only or no workflow files means execution, and mixed context means ask first; an explicit user instruction overrides the derived mode.
- 2026-11-15: Template v2 moved the five cold docs (`REQUIREMENTS`, `BACKLOG`, `DECISIONS`, `PROJECT`, `SESSIONS`) into the hidden `.aboot/` directory, keeping `AGENTS.md` + `BOARD.md` at the root — hidden over visible so the root stays clean and the dot-dir follows the hidden-config convention (`.github/`, `.claude/`); `AGENTS.md` becomes the entry point; `aboot add`/`update` migrate pre-v2 projects (manifest-gated, content preserved) so a re-run never creates duplicate `.aboot/` copies.
- 2026-11-15: Template v3 moved `BOARD.md` into `.aboot/`, leaving only `AGENTS.md` at the root — the hot/cold split no longer held because end users touch `REQUIREMENTS.md` too, so every workflow doc now lives in `.aboot/` and the root keeps just the agent entry point; `aboot add`/`update` migrate pre-v3 projects (manifest-gated, content preserved).
- 2026-11-15: Bumped 0.1.1 → 0.2.0 — the `aboot todo` → `aboot board` CLI rename and the template v2/v3 layout moves are breaking for 0.x users, so a minor bump rather than a patch.
- 2026-11-15: `aboot status` staleness marker shows only when a manifest exists (a manifest-less project is uninstalled, not stale) and is exposed as `"stale"` in `--json`.
- 2026-11-15: README dropped the v2/v3 layout-migration paragraphs — nothing was ever released before the `.aboot/` layout, so no external project ever needed migrating; the migration code stays (manifest-gated, tested) as a safety net.
